## 一、承担的主要任务

在本次"基于 AI 的数智化教学分析评价系统"课程设计中，我承担了从架构搭建、算法实现、前后端联调到部署交付的全栈开发工作，共提交代码 74 次。

**算法层**：我独立完成了 AI 算法服务的从零设计到落地，编写了算法需求文档、Agent 设计方案、出题设计等核心文档，实现了独立的 FastAPI 进程（8001 端口），涵盖 AI 出题、判题、报告生成、Agent 对话四类接口，并采用"三道防线"解析策略确保 LLM 输出不稳定时仍能降级。LLM 选型上，因通义千问额度耗尽果断切换至 DeepSeek，仅改四项配置即完成切换。

**Agent 与学情分析**：实现了 Agent 内核、工具注册、LLM 网关、会话记忆，注册 18 个工具，编写 106 个测试用例全部通过。重点攻关了 RAG 出题 Agent（向量检索优先、SQL 回退）与 AI 学情分析模块，设计了教学大纲考核点验证层（verifier），实现大小模型协同——大模型负责推理，规则引擎负责硬性校验。此外完成了 CT1-CT8 课程目标达成度建模与三级归因设计。

**工程与部署**：搭建了 monorepo 骨架与后端基础设施，修复了白屏、404、评价页超时（10s→18ms）等关键缺陷，编写了三端 Dockerfile、docker-compose 编排及 Windows Server 部署脚本与团队部署手册。

## 二、体会与自我评价

**架构决策的提前量决定返工量。** 项目初期将算法服务独立为单独进程、LLM 调用经网关代理隔离，这两项决策让后期供应商切换和算法迭代几乎零成本。我深刻认识到，模块边界的清晰划分比功能实现本身更重要。

**稳定性思维必须贯穿始终。** AI 应用的本质是不确定性——LLM 格式不可控、网络超时不可控、向量检索可能失效。我在每一层都设计了降级：解析失败有兜底、向量不可用回退 SQL、LLM 失败仍出模板报告。正是这些防御性编程让验收演示在网络抖动下仍稳定运行，这是我最大的工程收获。

**文档即设计。** 坚持将每个算法决策落盘成文档，既是思路整理，更是团队对齐的依据，比口头解释高效得多。

**不足之处**：部分前端 TS 类型错误未及时清理，部分提交信息过于简略，给回溯带来困难。这是我未来需要改进的工程习惯。

总体而言，本次课程设计让我在全栈工程能力和 AI 应用工程化上积累了宝贵实战经验，也明确了在代码规范性和团队分工上的提升方向。
