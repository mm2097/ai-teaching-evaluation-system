# 大小模型协同推理:教学大纲考核点验证

> 落地日期:2026-09-08
> 知识源:`docs/参考资料/Net教学大纲.docx`(计算机网络课程)
> 范围:学情诊断 + 主观题判分 两个场景

## 1. 背景与目标

当前系统 AI 能力(学情诊断、主观题判分、报告生成)全部依赖单一 DeepSeek 大模型。大模型在教育场景存在「逻辑漂移」与「幻觉生成」:诊断报告可能冒出课程不存在的知识点、判分评语可能依据不在考核范围内的内容。

本次引入「教学大纲」作为确定性知识源,构建**小模型验证层**:大模型先出结果,小模型用规则+向量检索做考核点对齐验证,产出校验报告 + 置信度。

### 「小模型」的工程定义

不是另一个 LLM,而是**确定性验证器**——基于结构化考核点规则 + TF-IDF 语义召回的规则引擎。

| 维度 | 大模型(DeepSeek) | 小模型(验证器) |
|---|---|---|
| 职责 | 全局数据解析、语义理解、生成评语/诊断/判分依据 | 具体逻辑验证:考核点对齐、幻觉检测、覆盖度 |
| 成本 | 按 token 计费 | 零额外 token |
| 延迟 | 1-2s/次 | <50ms/次 |
| 确定性 | 概率生成,可能漂移 | 确定性规则,可复现 |
| 失败模式 | 幻觉、漂移 | 漏报(同义表述未命中) |

**为何不用另一个小 LLM 做验证**:小 LLM 自身也会幻觉,验证效果不可靠;且延迟翻倍、成本翻倍。规则验证器对「考核点对齐」这类确定性问题是更优解——教学大纲是封闭知识集,规则匹配精确可控。

## 2. 架构总览

```
大模型(DeepSeek)出评语/诊断/判分依据
        │
        ▼
小模型验证层(algorithm/src/verifier.py)
        │
        ├─ 考核点规则库(syllabus_parser 解析大纲得到)
        │    └─ 5 章 × {教学目标/重点/难点/内容/学时} → kp_terms
        ├─ 对齐校验:输出提及的知识点是否落在大纲 key_points/content_keywords
        ├─ 幻觉校验:硬幻觉(跨领域黑词)+ 软幻觉(英文术语不在大纲)
        └─ 覆盖校验:应覆盖章节中被提及的比例
        │
        ▼
VerifyReport{aligned_kps, hallucinated_kps, coverage, confidence, flag, notes, matched_chapters}
```

## 3. 核心数据:考核点(CheckPoint)

规则解析大纲得到结构化考核点库。计网大纲 5 章,每章拆出:

| 字段 | 来源 | 示例 |
|---|---|---|
| chapter | 章节标题 | 第一章、计算机网络概论 |
| code | 章节编号 | ch1 |
| objectives | 教学目的与要求 | 了解因特网发展... |
| key_points | 教学重点(切分) | [因特网组成, 计算机网络概念, 分组交换技术, ...] |
| difficulties | 教学难点 | [分组交换原理, ...] |
| content | 教学内容原文 | 因特网概述、组成... |
| content_keywords | 教学内容切分 | [因特网概述, 组成, ...] |
| hours | 学时 | 6 |
| kp_terms | 上述四类合并去重 | (供匹配/向量化) |

额外抽取:课程目标 CT1-CT8(知识/能力/素养三类)、考核方式(平时30%+实践30%+期末40%)。

**存储**:进程内常量(`syllabus_data.py` 的 `lru_cache`),不建数据库表。本期硬编码计网(courseId=1)。

## 4. 实现分解

### 4.1 大纲解析器 `algorithm/src/syllabus_parser.py`

- 纯函数,python-docx 抽取正文段落(不抽表格,避免课程目标矩阵里的「第1章」噪声)
- 正则 `第([一二...])章[、\s]*(.+)` 识别章节边界
- 五个标签正则提取:`教学目的与要求`/`教学重点`/`教学难点`/`教学内容`/`学时分配`
- 解析失败的章节降级为整章文本块(不阻断)
- 课程目标/考核方式单独从表格抽取

### 4.2 小模型验证器 `algorithm/src/verifier.py`(核心)

`verify_against_syllabus(llm_output, context, course_id) -> VerifyReport`

**三项校验**:

1. **对齐校验 aligned**:遍历各章 `kp_terms`,字符串包含匹配 → `aligned_kps` + `matched_chapters`
2. **幻觉校验 hallucinated**:
   - 硬幻觉:命中跨领域黑词表(量子、神经网络、区块链、基因、傅里叶...)= 与计网明显无关 → `hallucinated_kps`
   - 软幻觉:输出里的英文术语(长度≥3)不在大纲关键词 → 记 notes(不进 hallucinated_kps,避免误杀同义表述)
3. **覆盖校验 coverage**:
   - 诊断场景:`weak_points` 对应章节中被提及的比例(无 weak_points 则全部章节)
   - 判题场景:题干对应章节(单题不要求覆盖多章,阈值=0)

**置信度公式**:`confidence = aligned/(aligned + 2*hallucinated + 1) * 0.7 + coverage * 0.3`
- 幻觉权重 2x 惩罚;有硬幻觉时置信度压到 ≤0.3

**flag 判定**:
- 有硬幻觉 → `warn`
- 覆盖低于场景阈值且有对齐 → `warn`
- 否则 → `pass`
- 无大纲/异常 → `skipped`

**场景阈值**:`diagnosis=0.4`(诊断要覆盖薄弱点)、`judge=0.0`(单题不要求覆盖)、`report=0.3`

### 4.3 TF-IDF 工具 `algorithm/src/tfidf.py`

自包含轻量 TF-IDF + 余弦(中文按字 + 英文按词),与 backend `dedup.py` 同构。本期 verifier 的对齐/幻觉用字符串匹配,TF-IDF 留作后续向量召回升级用。

### 4.4 接入学情诊断

**位置**:`backend/app/services/agent/base.py` 的 `run_agent_stream`

诊断 LLM 产出 final_answer 后、补兜底文案前,yield `verify` 事件:

```python
if agent_type == "diagnosis" and llm_produced:
    report = verify_diagnosis(final_answer, course_id=course_id or 1)
    if report is not None:
        yield {"type": "verify", "step": max_steps, "report": report}
```

- `verify_diagnosis`(`llm_proxy.py` helper)调 8001 `/verify`,10s 超时
- **失败不阻断**:返回 None 时跳过 verify 事件,诊断报告正常出
- 仅 diagnosis 场景触发(qa/exam/tutor 不触发)
- 仅验证 LLM 真实产出(非兜底文案)

### 4.5 接入主观题判分

**位置**:`algorithm/src/judge.py` 的 `judge_answer`

判分成功(normal)后,对 `reason + rubric_points` 做验证,附加到 `JudgeResponse.verify_report`:
- `JudgeResponse` 新增 `verify_report: dict | None` 字段
- **不改 `total_score`/`flag`**(判分优先,验证是参考)
- 失败不阻断判分

**后端透传**:
- `POST /answer-records`(学生提交简答题):存 `verify_report` 到 `StudentAnswerRecord.verify_report`(JSON 字符串),响应带回
- `GET /answer-records/{id}` 详情:返回 `verifyReport` 字段
- `POST /judge/short-answer`(老师批改):响应带 `verify_report`

### 4.6 algorithm 端点 `POST /verify`

```python
class VerifyRequest(BaseModel):
    llm_output: str
    scene: str = "diagnosis"  # diagnosis/judge/report
    question_stem: str | None = None
    weak_points: list[str] | None = None
    course_id: int = 1
```

纯规则验证,无 LLM Key 也能工作。失败返回 `flag=skipped` 报告(不抛 5xx)。

## 5. 前端展示

### 5.1 诊断校验卡片(`DiagnosisView.vue`)

诊断报告下方展示「🔬 大纲考核点校验」卡片:
- flag 标签(通过/存在超纲/已跳过)+ 置信度 + 覆盖度 + 命中章节
- 对齐考核点(绿色 tag 列表)
- 疑似超纲/幻觉(红色 tag 列表)
- 说明文字

事件链:`后端 SSE verify 事件 → agent.ts 映射为 AgentStreamEvent.verify → DiagnosisView 写入 verifyReport ref`

### 5.2 判题校验展示(`QuizAnswerView.vue`)

AI 判分块内追加「🔬 大纲校验」标签:
- flag + 置信度
- 疑似超纲知识点(红)
- 对齐考核点(绿)

数据来自 `GET /answer-records/{id}` 的 `verifyReport` 字段。

## 6. 设计要点(对齐项目约定)

1. **稳定性优先**:验证层全程 try/except,失败只降级不阻断;判题 `flag` 不因验证改变;诊断 verify 事件缺失前端照常渲染报告;algorithm `/verify` 失败返回 skipped 不抛 5xx。
2. **复用现有模式**:三道防线 JSON 解析、TF-IDF 余弦、SSE 事件流、MockLLMProxy 测试注入、database.py 迁移函数模式——都不发明新轮子。
3. **algorithm 单一职责**:algorithm 做无状态验证,不碰 SQL;诊断循环/工具执行留在 backend。
4. **零新依赖**:algorithm 侧用自写 TF-IDF,不引入 chromadb/openai(它们在 backend)。
5. **数据库迁移幂等**:`_migrate_student_answer_verify` 用 `inspect` 检查列存在性,每次启动安全执行。

## 9. 范围边界(本期不做)

- ❌ 不建 Syllabus/CheckPoint 数据库表(只计网,硬编码)
- ❌ 不做大纲上传接口/多课程支持
- ❌ 不接入报告增强(reporter.py)——留下一期
- ❌ 不做「验证失败自动重写大模型」闭环(独立验证层,非闭环)
- ❌ 不在 algorithm 引入 chromadb(用自写 TF-IDF)
