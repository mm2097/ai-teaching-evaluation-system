# 课程目标达成度分析：业务建模与设计方案

> 状态：设计稿（2026-09-10）
> 模块：智能分析 > 课程目标达成度
> 路由：`/analysis/ct-achievement`（teacher）
> 定位：参照《计算机网络技术》教学大纲，为每位学生构建 **CT1–CT8 课程目标维度** 的个人画像，量化各课程目标的达成情况，输出达成度雷达 + 达成等级 + 归因建议。

---

## 0. 背景与目标

### 0.1 为什么做

现有学情分析的能力维度是"学业水平 / 学习态度 / 学习进步 / 知识掌握"四维（`evaluation.py`），这是**通用教学评价维度**，与具体课程的教学大纲脱节。工程教育认证（OBE）与课程考核的核心理念是"以学生为中心、以产出为导向"，要求回答的是：

> 这门课的 8 个课程目标（CT1–CT8），每位学生分别达成到什么程度？哪个目标没达成？为什么？怎么补？

这是教学大纲闭环的最后一环，也是 MVP v1.1 旗舰"C1 诊断 → A3 出题"之后，把诊断维度从"知识点"上抬到"课程目标"层级的关键一步。

### 0.2 与现有功能的关系

| 现有功能 | 维度 | 局限 |
|---|---|---|
| 学情画像（`StudentProfile`） | 学业/态度/进步 | 通用维度，不挂钩课程目标 |
| 知识点掌握度（`KnowledgeMastery`） | 知识点 | 颗粒度太细，无法回答"CT2 达成了吗" |
| AI 学情诊断（`diagnosis` Agent） | 综合归因 | LLM 自由生成，无结构化 CT 维度评分 |
| 小模型验证（`verifier`） | 考核点对齐 | 验证 LLM 输出是否超纲，**不做学生侧达成度计算**；CT1-CT8 已解析但注释为"可选，未实装" |

**本功能定位：把 CT1–CT8 从"大纲里的一张表"变成"每位学生画像的一个轴"。** 它不是替代四维评价，而是在四维评价之上叠加一层"课程目标达成度"视图——回答教学大纲视角的达成情况。

### 0.3 核心挑战（已识别）

1. **关联链断裂**：题目（`AiQuestion.point_id`）→ 知识点（`KnowledgePoint`）这条链存在，但**知识点 → 课程目标(CT) 没有映射**。大纲表3 提供"章节 → CT"矩阵，但代码未结构化。
2. **素养类目标无硬数据**：CT7（职业道德）、CT8（团队协作）来自小班讨论/课程设计，没有客观题答题数据，只能从考核批次成绩间接推断。
3. **能力类目标难量化**：CT4（分析解决问题）、CT5（工具使用）、CT6（编程实现）主要来自实验/课程设计/简答题，需从主观题得分和考核类型推断。
4. **本期只支持计网一门**：大纲解析硬编码 `course_id=1`，多课程支持是后续演进。

## 1. 业务建模

### 1.1 课程目标 CT1–CT8 完整定义

来源：`docs/参考资料/Net教学大纲.docx` 表1（已由 `parse_course_objectives()` 解析验证）。

| 编号 | 类别 | 课程目标描述 |
|------|------|------|
| CT1 | 知识 | 掌握计算机网络通信技术基本原理、重要术语和基本方法 |
| CT2 | 知识 | 掌握网络体系结构 TCP/IP 分层技术的原理、协议、网络拓扑结构 |
| CT3 | 知识 | 掌握 IPV4 网络地址划分方法和主流局域网技术 |
| CT4 | 能力 | 具备分析计算机网络问题并通过掌握的方法解决问题的能力 |
| CT5 | 能力 | 具备使用网络测量工具从工程角度观察和分析因特网协议执行过程的能力 |
| CT6 | 能力 | 具备编程实现计算机网络基本算法和协议的能力 |
| CT7 | 素养 | 具备良好科学素质、爱国精神、社会责任感和职业道德 |
| CT8 | 素养 | 具备良好的团队协作精神 |

### 1.2 课程内容 → CT 映射矩阵（大纲表3，**核心桥梁**）

这是把"章节/教学环节"映射到"课程目标"的权威矩阵：

| 课程内容 \ CT | CT1 | CT2 | CT3 | CT4 | CT5 | CT6 | CT7 | CT8 |
|---|---|---|---|---|---|---|---|---|
| 第1章 计算机网络概论 | ● | | | | | | | |
| 第2章 应用层 | ● | ● | | ● | | | | |
| 第3章 传输层 | ● | ● | | ● | | | | |
| 第4章 网络层 | ● | ● | ● | ● | | | | |
| 第5章 链路层与局域网 | ● | ● | ● | ● | | | | |
| 小班讨论 | | | | ● | ● | ● | ● | ● |
| 课程实验 | | | | ● | ● | ● | ● | ● |
| 课程设计 | | | | ● | ● | ● | ● | ● |

**映射规律**：
- **知识类 CT1–CT3**：来自第1–5章课堂讲授（CT1 全章节，CT2 第2–5章，CT3 第4–5章）
- **能力类 CT4–CT6**：课堂讲授中培养分析能力（CT4），实验/课程设计培养工具使用（CT5）和编程能力（CT6）
- **素养类 CT7–CT8**：仅来自小班讨论/课程实验/课程设计

### 1.3 考核方式与权重（大纲第五节）

```
总成绩 = 平时成绩(30%) + 实践成绩(30%) + 期末成绩(40%)
平时成绩 = 考勤 + 课堂表现 + 测验
实践成绩 = 小班讨论 + 课程设计 + 实验成绩
期末成绩 = 期末考试（闭卷）
```

对应 `ExamBatch.batch_type`：1=平时 / 2=实验 / 3=期中 / 4=期末 / 5=考勤。

### 1.4 数据源 → CT 的可观测映射（**业务建模核心**）

学生侧能观测到的数据，如何归因到 CT？这是达成度计算的业务基础。按下表建立"可观测证据 → CT"的归因：

| 数据源 | 观测指标 | 归因到 CT | 权重说明 |
|---|---|---|---|
| `StudentAnswerRecord`（AI 答题） | 题目所属知识点 → 章节 → CT1/CT2/CT3/CT4 的正确率 | CT1–CT4 | 客观题直接判分；简答题 AI 判分 |
| `CourseTestDetail`（试卷大题扣分） | 每题知识点字段 → 章节 → CT 的得分率 | CT1–CT4 | 期中/期末试卷，5 道大题扣分 |
| `IndividualScore`（单项成绩） | 按考核类型映射：平时→CT1-4、实验→CT4-6、期末→CT1-4 | CT1–CT6 | 按 batch_type 分流 |
| `AttendanceSheet`（考勤） | 出勤率 | CT7（间接：学习态度≈职业素养） | 弱归因 |
| `ParticipationSheet`（课堂参与） | 参与率 | CT7（课堂讨论≈素养表现） | 弱归因 |
| 实验报告/课程设计成绩（`IndividualScore` batch_type=2） | 得分率 | CT5、CT6、CT7、CT8 | 实践环节是 CT5-8 主来源 |
| 小班讨论成绩 | 得分率 | CT4、CT7、CT8 | 素养类主要证据 |

**建模要点**：
- 同一数据源可归因到多个 CT（如期末试卷大题既支撑 CT1 知识又支撑 CT4 分析能力）——用**权重分配**处理，权重之和为 1。
- 素养类 CT7/CT8 没有直接客观题证据，用"实践环节成绩 + 考勤 + 课堂参与"组合推断，并在画像中标注"推断置信度低"。
- **知识点 → 章节 → CT** 这条链是知识类 CT 的命脉，必须先打通。

### 1.5 达成度定义

**课程目标达成度（CT Achievement Degree）**：学生在某课程目标 CTi 上的表现相对于该目标期望水平的达成比例，取值 0–100。

```
CT_i_达成度 = Σ(证据项得分率 × 该证据对 CT_i 的归因权重) × 100
```

达成等级（与系统现有 `score_to_level` 五档对齐）：

| 达成度 | 等级 | 含义 |
|---|---|---|
| ≥85 | 优秀 | 全面达成，可进阶 |
| 70–84 | 良好 | 基本达成，个别薄弱 |
| 60–69 | 合格 | 勉强达成，需巩固 |
| 40–59 | 不足 | 未达成，需重点干预 |
| <40 | 严重不足 | 严重未达成，预警 |

> 注：达成度阈值比综合评价（90/80/70/60）低 5 分，因为"达成"标准比"优秀"标准更宽容（OBE 达成度评价惯例：达成 60% 即算合格达成）。

### 1.6 全局数据流


## 2. 关键缺口与打通方案

达成度计算的前提是"知识点 → CT"映射链。当前三处缺口：

### 缺口1：知识点表无 CT 字段

**现状**：`KnowledgePoint` 只有 `point_id / module_id / point_name / description / sort_num`，无课程目标字段。

**方案**：给 `KnowledgePoint` 加 `course_objectives: Optional[str]` 字段（逗号分隔的 CT 编号，如 `"CT1,CT2,CT4"`），含义是"该知识点主要支撑哪些课程目标"。

- 取值来源：先用大纲表3"章节→CT"矩阵自动初始化（知识点按所属模块/章节匹配），再支持教师在管理页手工微调。
- 为何用逗号分隔字符串而非关联表：一个知识点通常支撑 1–3 个 CT，关联表过度设计；与现有 `StudentProfile.study_tags`（逗号分隔）风格一致。
- 计网 7 个种子里知识点的初始映射（按大纲表3）：

| 知识点 | 所属模块（≈章节） | 映射 CT |
|---|---|---|
| OSI 七层模型 | 网络体系结构（概论） | CT1, CT2 |
| TCP/IP 四层模型 | 网络体系结构（概论/各章） | CT1, CT2 |
| 以太网帧格式 | 数据链路层（第5章） | CT1, CT2, CT3 |
| ARP 协议 | 数据链路层（第5章） | CT1, CT2, CT3 |
| TCP 三次握手 | 传输层（第3章） | CT1, CT2, CT4 |
| TCP 四次挥手 | 传输层（第3章） | CT1, CT2, CT4 |
| UDP 协议特点 | 传输层（第3章） | CT1, CT2, CT4 |

### 缺口2：考核批次 → CT 的类型映射缺失

**现状**：`ExamBatch.batch_type`（1平时/2实验/3期中/4期末/5考勤）存在，但没有"该批次支撑哪些 CT"的映射。

**方案**：用**常量映射表**（不建库），按 batch_type 推断 CT 归因权重：

```python
BATCH_TYPE_CT_WEIGHTS = {
    1: {"CT1": 0.3, "CT2": 0.3, "CT3": 0.2, "CT4": 0.2},          # 平时（测验/作业）
    2: {"CT4": 0.2, "CT5": 0.3, "CT6": 0.3, "CT7": 0.1, "CT8": 0.1}, # 实验
    3: {"CT1": 0.25, "CT2": 0.25, "CT3": 0.25, "CT4": 0.25},        # 期中
    4: {"CT1": 0.25, "CT2": 0.25, "CT3": 0.25, "CT4": 0.25},        # 期末
    5: {"CT7": 0.6, "CT8": 0.4},                                     # 考勤（素养弱归因）
}
```

> 期末/期中试卷若用了 `CourseTestDetail` 的大题知识点字段，则优先按知识点→CT 精确归因，而非用 batch_type 均分。

### 缺口3：素养类 CT（CT7/CT8）证据薄弱

**现状**：无专门的职业道德/团队协作评分数据。

**方案**：CT7/CT8 用"实践环节成绩 + 考勤 + 课堂参与"组合推断，公式：
```
CT7 ≈ 0.5 × 实践成绩得分率 + 0.3 × 考勤率 + 0.2 × 课堂参与率
CT8 ≈ 0.6 × 实践成绩得分率 + 0.4 × 课堂参与率
```
在画像中标注 `confidence: "low"`，提示"基于实践环节间接推断"。

## 3. 达成度计算算法

### 3.1 算法分层

```
ct_achievement.py（新建，backend/app/services/）
├── _knowledge_ct_scores()      # 知识点→CT（CT1-CT3 精确归因）
├── _batch_ct_scores()          # 考核批次→CT（CT1-CT6 类型归因）
├── _literacy_ct_scores()       # 素养类推断（CT7-CT8）
├── compute_student_ct()        # 单学生 CT 达成度
├── compute_class_ct()          # 班级 CT 达成度（均值）
└── persist_ct_achievement()    # 落库
```

### 3.2 单学生 CT 达成度算法（核心）

```python
def compute_student_ct(session, student_id, course_id) -> CTAchievement:
    ct_scores = {f"CT{i}": None for i in range(1, 9)}  # None=无证据
    ct_confidence = {}  # "high"/"medium"/"low"

    # === CT1-CT4：知识点精确归因（首选）===
    # 1. 取学生各知识点掌握度（compute_student_mastery 已有）
    masteries = compute_student_mastery(session, student_id, course_id)
    # 2. 每个知识点按其 course_objectives 字段分配到 CT
    ct_kp_acc = {f"CT{i}": [] for i in range(1, 5)}  # CT1-CT4
    for m in masteries:
        kp = session.get(KnowledgePoint, m.point_id)
        cts = parse_ct_field(kp.course_objectives)  # "CT1,CT2" -> ["CT1","CT2"]
        for ct in cts:
            if ct in ct_kp_acc:
                ct_kp_acc[ct].append(m.accuracy)
    for ct, accs in ct_kp_acc.items():
        if accs:
            ct_scores[ct] = round(sum(accs) / len(accs), 1)
            ct_confidence[ct] = "high"

    # === CT1-CT4 补充：试卷大题扣分归因 ===
    # CourseTestDetail.questionN_knowledge -> 知识点 -> CT
    test_ct_acc = aggregate_test_detail_by_ct(session, student_id, course_id)
    for ct, acc in test_ct_acc.items():
        if ct_scores[ct] is None:
            ct_scores[ct] = acc
            ct_confidence[ct] = "medium"
        else:
            # 与知识点掌握度融合：取加权平均
            ct_scores[ct] = round(ct_scores[ct] * 0.6 + acc * 0.4, 1)

    # === CT4-CT6：考核批次类型归因 ===
    batch_ct = aggregate_batch_scores_by_ct(session, student_id, course_id)
    for ct, score in batch_ct.items():
        if ct_scores[ct] is None:
            ct_scores[ct] = score
            ct_confidence[ct] = "medium"

    # === CT7-CT8：素养推断 ===
    literacy = _literacy_ct_scores(session, student_id, course_id)
    for ct, score in literacy.items():
        ct_scores[ct] = score
        ct_confidence[ct] = "low"

    # === 达成等级 + 总体达成度 ===
    levels = {ct: degree_to_level(s) if s is not None else None
              for ct, s in ct_scores.items()}
    valid = [s for s in ct_scores.values() if s is not None]
    overall = round(sum(valid) / len(valid), 1) if valid else 0.0

    return CTAchievement(
        student_id=student_id, course_id=course_id,
        ct_scores=ct_scores, ct_levels=levels, ct_confidence=ct_confidence,
        overall=overall, overall_level=degree_to_level(overall),
    )
```

**考核批次按 CT 聚合**（`aggregate_batch_scores_by_ct`）：

### 3.4 班级 CT 达成度

```python
def compute_class_ct(session, course_id) -> ClassCTAchievement:
    student_ids = ...
    per_student = [compute_student_ct(session, sid, course_id) for sid in student_ids]
    # 每个 CT 取全班均值 + 标准差（看离散度）
    ct_avg = {ct: mean([s.ct_scores[ct] for s in per_student if s.ct_scores[ct] is not None])
              for ct in CT_CODES}
    ct_std = {ct: std(...) for ct in CT_CODES}
    # 达成率 = 该 CT 达成度≥60 的学生占比
    ct_pass_rate = {ct: count(s.ct_scores[ct] >= 60) / total for ct in CT_CODES}
    return ClassCTAchievement(ct_avg, ct_std, ct_pass_rate, per_student)
```

## 4. 数据模型设计

### 4.1 新增表：`ct_achievement`（学生 CT 达成度落库）

```python
# backend/app/models/analysis.py 追加
class CTAchievement(SQLModel, table=True):
    """课程目标达成度记录表 ct_achievement。

    联合唯一索引: (course_id, student_id)
    每次 refresh_course_analysis 时重算覆盖。
    """
    __tablename__ = "ct_achievement"
    __table_args__ = (UniqueConstraint("course_id", "student_id", name="uq_ct_course_student"),)

    achievement_id: Optional[int] = Field(default=None, primary_key=True)
    course_id: int = Field(foreign_key="course.course_id", index=True)
    student_id: int = Field(foreign_key="student.student_id", index=True)

    # 8 个 CT 达成度（0-100，None 表示无证据）
    ct1_score: Optional[float] = Field(default=None)
    ct2_score: Optional[float] = Field(default=None)
    ct3_score: Optional[float] = Field(default=None)
    ct4_score: Optional[float] = Field(default=None)
    ct5_score: Optional[float] = Field(default=None)
    ct6_score: Optional[float] = Field(default=None)
    ct7_score: Optional[float] = Field(default=None)
    ct8_score: Optional[float] = Field(default=None)

    # 各 CT 置信度（high/medium/low），逗号分隔，顺序同 CT1-8
    ct_confidence: Optional[str] = Field(default=None, max_length=64)

    overall_score: float          # 总体达成度（有证据 CT 的均值）
    overall_level: str            # 总体达成等级
    weak_cts: Optional[str] = Field(default=None, max_length=64)   # 达成度<60 的 CT 编号，逗号分隔
    strong_cts: Optional[str] = Field(default=None, max_length=64) # 达成度≥85 的 CT 编号
    update_time: datetime = Field(default_factory=datetime.now)
```

**设计权衡**：
- 用列式（ct1_score~ct8_score）而非 JSON：8 个 CT 固定不变，列式便于 SQL 聚合（班级均值 `AVG(ct1_score)`）和前端直接取值。
- `ct_confidence` 用逗号分隔串而非 8 列：置信度只是展示提示，不做聚合。
- 与 `StudentProfile` / `StudentEvaluationResult` 同级，独立落库，不污染现有四维评价。
