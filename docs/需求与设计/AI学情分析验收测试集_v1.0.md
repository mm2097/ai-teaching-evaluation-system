# AI 学情分析验收测试集 v1.0

> **文档定位**:针对"智能分析 > AI 学情分析"功能(`/analysis/diagnosis`)的可执行验收测试集。每个用例含输入/预期输出/验收点,可直接拿去问答系统、对照判断是否通过。
> **覆盖**:工具编排 + 班级诊断 + 学生诊断 + SSE 流式 + 追问 + 导出 + 干预联动 + 兜底 + 权限 + 全链路演示。
> **配套**:`AI学情分析Agent设计方案_v1.0.md`、`AI学情分析_原型_v1.0.html`、`MVP验收测试集_v1.0.md`。
> **日期**:2026-09-07

## 0. 使用说明

### 测试方法
1. 准备种子数据(见第 1 节,复用 MVP 测试集的 conftest.py 种子)
2. 启动后端 + algorithm 服务(8001,DeepSeek 可用)
3. 按用例逐条执行,记录实际输出
4. 对照"验收点"判断 PASS / FAIL
5. 汇总量化指标(第 13 节)判断整体是否达标

### 缺陷分级
- **Blocker**:阻断主流程,必须修复才能验收(如诊断不返回报告、SSE 断流、500 报错)
- **Major**:功能受损但不阻断(如归因缺失、建议无优先级)
- **Minor**:体验问题(如过程区折叠默认态、文案),可延后

### 用例编号规则
`TC-DIAG-{模块}-{序号}`,模块:TOOLS/CLASS/STUDENT/SSE/ASK/EXPORT/ACT/SAFE/DEMO

## 2. 工具编排测试(TC-DIAG-TOOLS)★核心

### TC-DIAG-TOOLS-01: 班级诊断工具调用顺序 ★关键
- **输入**:POST `/api/v1/agent/chat/stream`,body 含 `message="请对班级做全面学情诊断"`,`course_id=C001 课程`,`agent_type=diagnosis`,分析对象=班级
- **预期**:SSE 事件流中,`tool_call` 事件按诊断逻辑依次出现,至少包含:
  1. `get_course_overview`(总览先行)
  2. `get_weak_knowledge_points` 或 `get_knowledge_mastery`(知识点)
  3. `get_warning_students`(预警)
  4. `get_score_trend`(趋势)
- **验收点**:✅ 总览工具最先调用;✅ 工具数 ≥ 4;✅ 覆盖成绩/知识点/预警三个维度
- **类型**:正常

### TC-DIAG-TOOLS-02: 学生诊断工具调用差异 ★
- **输入**:分析对象=学生 S020,`agent_type=diagnosis`
- **预期**:工具调用包含 `get_student_detail`(学生专属),且 `get_knowledge_mastery` 带个人维度
- **验收点**:✅ 调用 `get_student_detail`;✅ 与班级诊断的工具集不同(个人化)
- **类型**:正常

### TC-DIAG-TOOLS-03: 维度勾选影响工具调度 ★
- **输入**:仅勾选"知识点"维度(取消成绩/考勤/预警)
- **预期**:AI 只调用知识点相关工具(`get_knowledge_mastery`/`get_weak_knowledge_points`),不调成绩/考勤工具
- **验收点**:✅ 工具调用与勾选维度一致;✅ 不越界调用未勾选维度
- **类型**:规则

### TC-DIAG-TOOLS-04: 工具调用次数上限
- **输入**:详细深度班级诊断
- **预期**:工具调用次数 ≤ max_steps(diagnosis 建议 8-10)
- **验收点**:✅ 不超上限;✅ 不陷入循环调用
- **类型**:边界

### TC-DIAG-TOOLS-05: 工具结果回灌正确
- **方法**:检查 SSE `tool_result` 事件
- **预期**:每个 `tool_call` 都有对应 `tool_result`,结果摘要非空
- **验收点**:✅ 调用-结果一一对应;✅ 无空结果(工具失败时有错误提示)
- **类型**:完整性

## 3. 班级诊断测试(TC-DIAG-CLASS)

### TC-DIAG-CLASS-01: 班级报告结构完整性 ★
- **输入**:班级诊断完成后,AI 返回的 content(JSON)
- **预期输出**:
  ```json
  {
    "scope": "class",
    "overall": { "grade": "...", "score": ..., "summary": "..." },
    "findings": { "strengths": [...], "risks": [...] },
    "causes": [...],
    "suggestions": [...],
    "radar": {...},
    "meta": { "source": "llm", "toolsUsed": [...] }
  }
  ```
- **验收点**:✅ 6 个顶层字段齐全;✅ `findings.strengths` 和 `risks` 均非空;✅ `suggestions` ≥ 1 条
- **类型**:正常

### TC-DIAG-CLASS-02: 薄弱点识别准确性 ★关键
- **输入**:班级诊断(基于 MVP 种子)
- **预期**:`findings.risks` 或 `causes` 中命中"哈夫曼"和"线索二叉树"(正确率 35%/45%)
- **验收点**:✅ Top 薄弱点命中预设;✅ 不误报"遍历"为薄弱(正确率 80%)
- **类型**:准确性

### TC-DIAG-CLASS-03: 优势识别
- **预期**:`findings.strengths` 命中"遍历"或班级出勤/互动优势
- **验收点**:✅ 优势非空;✅ 与种子数据一致
- **类型**:准确性

### TC-DIAG-CLASS-04: 预警学生纳入风险
- **预期**:`findings.risks` 中包含 S020(红色预警)或其引用
- **验收点**:✅ 红色预警学生出现在风险发现中
- **类型**:联动

### TC-DIAG-CLASS-05: 综合评级合理性
- **预期**:`overall.grade` ∈ {A,B,C,D},`overall.score` ∈ [0,100],与班级均分 72 大致匹配(B 或 C)
- **验收点**:✅ 评级非空;✅ 评级与数据不矛盾(均分 72 不会评 A)
- **类型**:合理性

### TC-DIAG-CLASS-06: 干预建议带优先级与工具提示 ★
- **预期**:每条 `suggestions` 含 `priority`(高/中/低)+ `toolHint`(weakness_driven_quiz/notify/talk)
- **验收点**:✅ 优先级字段存在;✅ toolHint 可路由到具体干预动作
- **类型**:结构

### TC-DIAG-CLASS-07: 归因带数据引用
- **预期**:每条 `causes` 含 `dataRef`(引用的工具名)
- **验收点**:✅ 归因可追溯;✅ dataRef 对应已调用的工具
- **类型**:可解释性

### TC-DIAG-CLASS-08: 空班级兜底
- **输入**:选一个无学生的班级
- **预期**:返回友好提示"该班级暂无学情数据",不报 500,过程区不卡死
- **验收点**:✅ 不崩;✅ 可读错误
- **类型**:异常

## 10. 全链路演示场景(TC-DIAG-DEMO)★验收重头戏

### TC-DIAG-DEMO-01: 班级诊断→干预闭环演示

**场景**:张老师从班级诊断到生成干预任务,全流程跑通。

| 步骤 | 操作 | 预期 | 验收点 |
|------|------|------|--------|
| 1 | 选 C001 班级,点"开始 AI 分析" | SSE 流式展示工具调用 | ✅ 过程可见 |
| 2 | 等待诊断完成 | 渲染班级报告(B 级,图论薄弱) | ✅ 报告完整 |
| 3 | 查看关键发现 | 命中哈夫曼/线索薄弱,S020 红色预警 | ✅ 准确性 |
| 4 | 查看归因 | 图论失分占比 + S020 态度问题 | ✅ 可解释 |
| 5 | 点"生成练习" | 跳转 AI 出题,注入哈夫曼 | ✅ C1→A3 联动 |
| 6 | 追问"S020 还能赶上吗" | AI 结合诊断上下文回答 | ✅ 追问继承 |
| 7 | 点"导出报告"PDF | 下载含四段的 PDF | ✅ 导出 |
| 8 | 点"生成干预任务" | 聚合出题+通知任务清单 | ✅ 闭环 |

**整体验收**:8 步全通 = 功能通过。
